# 图标改为位图可覆盖：`payload.iconImages` + 逐图标回落

- **状态**：已接受（2026-11-16）
- **取代**：`ADR-0005` 中「图标只做绘制参数、不随包下发资源」的结论（见该文 Status 的 amend 注记）
- **相关**：`ADR-0003`（皮肤包契约）、`ADR-0005`（资源通道）、`ADR-0006`（冷启动不碰网络）

## 背景

`ADR-0005` 当时的选择是：把 `DrawScope` 手绘图标改造成**可序列化的绘制参数**（`NavIconGeometry`），
并明确否决了「图标随包下发 VectorDrawable」与「引入图片加载框架」两条路，理由是
「数据化后参数表已足够表达」。

这带来一个实际后果：**皮肤包能调图标线宽，但换不了图标长什么样**。
B 端做视觉焕新时，四个导航图标（grid / calendar / compass / person）的形状仍然锁死在 APK 里，
「皮肤 = 主题 + 图标 + 字体」里「图标」那一半只落地了参数、没落地形状。

维护者要求补齐这一点：**皮肤包可以替换图标文件**（`ResourcePayload` 增加图标文件映射）。

## 决策

皮肤包的 `payload` 段新增**可选**子段 `iconImages`，把图标名映射到包内**位图相对路径**：

```json
{
  "payload": {
    "iconStrokes": { "grid": 0.085 },
    "fontFileName": "fonts/brand.ttf",
    "iconImages": { "grid": "icons/grid.png", "person": "icons/person.webp" }
  }
}
```

三条硬规则（全部在 `SkinManifestParser.parseMap` 判定，纯 JVM 可测）：

1. **路径必须合法**：复用 `SkinPackIntegrity.checkPathAllowed` —— 无目录穿越、
   扩展名在既有白名单内（`png/webp/jpg/jpeg`，白名单早就含位图，无需扩容）。
2. **必须已在 `integrity.entries` 里声明**：否则整包拒绝。这条防的是
   「清单引用了包里夹带但没被 sha256 覆盖的文件」——完整性校验的覆盖面不能有缺口。
3. **未知图标名忽略，不阻断整包**：属 `ADR-0003` 第②层「同主版本未知字段忽略」。

**逐图标回落**（沿用 `ADR-0005` Q5=A 的粒度）：某个图标缺失、路径非法被剔、或运行时解码失败，
**只该图标**回落到内置几何绘制，其余照用。**不做整包切换**。

**渲染顺序**：`drawIconOverride(...)`（位图）优先；返回 `false` 时回落既有
`drawNavIcon(geometry, tint, strokeScale)`（几何）。两条路径的目标尺寸同一套逻辑，
视觉切换不会跳尺寸。

**染色语义**：位图按**单色图标**设计，用 `ColorFilter.tint` 染成主题色。
这样包内图不必关心配色，与几何图标共用同一套 tint（选中/未选中/填充进度都自动一致）。

## 被否的备选

| 备选 | 为什么不选 |
| --- | --- |
| 扩展 `NavIconGeometry` 加 `Custom(pathData)` 分支 | `pathData` 能表达任意形状，等于让包下发**绘制指令**而不是图像资源；安全面比位图更差，且要为 `DrawScope` 新写路径解析器 |
| 让包下发 VectorDrawable / XML | 需要 API 30 双路径 + 解析开销，`ADR-0005` 已否决；且与「位图」相比并无尺寸收益（图标只有 26dp） |
| 引入 `coil3` 等图片框架 | `ADR-0005` 已实测 `coil3` 3.6.3 的 AAR `minCompileSdk=37` 构建不过，为几十个图标引入图片框架不划算 |
| 位图替换后禁用几何绘制 | 会让「包只覆盖了一个图标」变成「其余图标消失」——违反逐资源回落 |

## 代价与边界

- **皮肤包格式多了一个可选段**：`schemaVersion` 主版本**不变**（`SUPPORTED_SCHEMA_MAJOR` 仍为 1），
  因为这是「同主版本新增可选字段」，旧客户端读到会按第②层忽略，不会炸。
- **渲染层多一条分支**：`NavIconPainter` 持有进程内位图缓存（按「路径 + mtime + 长度」为 key，
  上限 8 项）。不带缓存会在每一帧 `BitmapFactory.decodeFile`，把主线程打死。
- **密度适配**：本期约定包内位图按**图标显示尺寸的 2–3 倍**提供（导航图标 26dp → 建议 ≥78px）。
  本期不引入 `@2x/@3x` 目录约定 —— 图标太小，单张高清图已足够；若将来出现大尺寸位图需求再加。
- **不覆盖 launcher icon**：`ADR-0005` 已定「launcher icon 本期不做」，本决策不放宽。

## 影响

- `skin/SkinData.kt`：`ResourcePayload` 增 `iconImages`（默认空表）+ `iconImageOf(key)`。
- `skin/SkinPack.kt`：`SkinPackManifest` / `LoadedResources` 增 `iconImages`，`toPayload()` 带出。
- `skin/SkinManifestParser.kt`：`ManifestRaw` 增 `iconImages`，`parseMap` 做三条硬校验。
- `skin/FileSkinSource.kt`：启动路径把相对路径拼成**绝对路径**（与字体同一套做法）。
- `icon/NavIconPainter.kt`（新增）：位图解码 + 缓存 + 染色 + 失败回落。
- `shell/bar/NavRowContent.kt`：`Canvas` 里先试位图，失败再画几何。
- 测试：`skin/IconImageOverrideTest.kt`（7 个纯 JVM 用例）。

## 验证

- 纯 JVM：清单解析（含未知图标名忽略）、未在 entries 声明 → 整包拒绝、路径穿越 → 整包拒绝、
  非白名单扩展名 → 整包拒绝、`plan` 透传、`iconImageOf` 逐项回落。
- 构建：`compileDebugKotlin` / `compileReleaseKotlin` + 全量单测。
- 渲染：有包时位图生效、无包/解码失败时几何图标不受影响（默认路径零变化）。
