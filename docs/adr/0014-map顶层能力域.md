# ADR-0014 新增 `map` 顶层能力域承载校区地图与标注

- 状态：已采纳（2026-11-25）
- 相关：ADR-0008（顶层包按能力域切分）、ADR-0012（通用 WebView 独立成包）、`docs/specs/界面层.md`

## 背景

后端 `internal/classroom/maphandler.go` 已提供两条只读端点：`GET /classrooms/maps/:campus/meta`（元数据含标定参数、四角坐标、是否已上传/标定）与 `GET /classrooms/maps/:campus`（原始底图图片字节）。客户端 `net/api/ClassroomApi` 已接入。

产品需要的不是一个「显示图片的视图」，而是一组能力：

1. 地图图片**本地缓存优先**，不存在时才请求后端；
2. 在底图上做标注（点 / 文字 / 线，可设颜色）、能拖动；
3. 跳转外部地图软件（携带地点信息）。

这些能力横跨网络、文件缓存、DataStore、Compose Canvas、Android Intent，不是纯设计组件。

## 决策

新增**独立顶层能力域** `map`（单数具名），按 ADR-0008 分层：

```text
map/
├── model/   Annotation（点/线/文字 + 颜色 + campus）、MapViewport 等纯数据，零 android/compose
├── logic/   标注命中判定、geo: URI 构造、视口平移换算——纯 JVM 单测
├── data/    图片文件缓存（filesDir）、标注 DataStore（按 campus 分区）、经 net 取数的仓库
└── ui/      Compose Canvas 组件：显示底图 + 拖动 + 标注编辑
```

依赖方向 `model ← logic ← data ← ui`。`model/` 与 `logic/` 禁止 import `android.*` / `androidx.compose.*`。

### 关键约束

- **不复用 WebVPN 的 WebView 沙箱**，也不放在 `webpage`（ADR-0012）——地图是 Canvas 绘制，不是网页容器。
- **不放入 `design/`**：design 不认识业务域，且这里需要网络与存储。
- **不实现 `ClassroomMapView` 兼容**：工作区里 `LocationEditSheet.kt` 有他人未提交的引用，本次独立实现 `MapCanvas`，不覆盖、不补他们的代码。
- **geo: URI 用标准 `ACTION_VIEW`**，不依赖高德 SDK / key，让系统让用户选已装地图 App。
- **图片缓存落 `filesDir`**，标注 JSON 落 DataStore（按 campus 分区）；换机不迁移。

## 为什么不选其它方案

- **放 `design/`**：会迫使设计层 import 网络/存储，破坏 ADR-0008 的分层。
- **放 `timetable/ui/`**：不是共用能力，将来个人主页等处要用会复制。
- **用高德 SDK**：引入新依赖与 key 管理，且 geo: URI 已能满足「跳外部地图」需求。

## 后果

- 新增顶层包与 ADR，符合 ADR-0008「新增顶层包先写 ADR」。
- `map/model`、`map/logic` 可纯 JVM 单测（标注几何、URI 构造）。
- 图片缓存与标注持久化只在本域内，不侵入 `net`。
- 已知遗留：他人未提交的 `ClassroomMapView` / `isAmapKeyConfigured` 引用仍指向不存在的符号，属他们的工作，本次不处理。
