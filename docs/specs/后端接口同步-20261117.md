## 3 本轮的三个关键事实（都是读代码核实，不是推测）

### 3.1 帖子域的响应信封与 identity 域**不同**

identity 域成功时直接吐裸结构体；**帖子/公告/站内信都用信封，且每个端点不一样**：

| 端点 | 形状 |
| --- | --- |
| `GET /posts` | `{"items":[...],"next":"..."}` |
| `GET /posts/:id` | `{"data":{...},"replies":[...]}` |
| `POST /posts` | **HTTP 201** + `{"data":{...}}` |
| `PATCH /posts/:id` | `{"data":{...}}` |
| `POST /posts/:id/replies` | **HTTP 201** + `{"data":{replyView}}` |
| 删除 / 点赞 / 收藏 | `{"status":"ok"}` |

⇒ **不能共用一个 `PostDto`**，每个端点按自己的信封建 DTO。

### 3.2 `likedByMe` / `favoritedByMe` 只在详情里有值

后端注释明写：「这两个字段不进列表响应（列表不逐条查反应，成本高且用途低）」。
**列表里恒为 `null` 不是 bug**，已写进 DTO 注释。

### 3.3 `{"data":null}` 是正常状态

`GET /announcements/latest` 没有生效公告时返回 `c.JSON(200, gin.H{"data": nil})`。
**HTTP 仍是 200**，`data` 为 null 表示「当前没有公告」，不是错误。
另有 `/announcements/latest` 是 `:id` 路由的特例（取 `latest` 字面量），不是独立路由。
